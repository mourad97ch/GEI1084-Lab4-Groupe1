Shift (S1-S10) - Groupe 1 - Hatem
Branche : feature/shift (depuis dev/phase4, sans CMP ni BL).

Ce qui a change :
- phase4/src/shifter.vhd : shifter combinatoire, LSL et LSR logique.
  shamt = Instr(11:7), sh = Instr(6:5), bit4 = Instr(4).
  ASR, ROR et decalage par registre : hors portee, operande transmis tel quel.
- phase4/src/datapath.vhd : RD2 -> shifter -> entree d0 du mux ALUSrc.
  ExtImm (d1) n'est jamais decale. WriteData = RD2 non decale.
  Interface du datapath inchangee (aucun port ajoute ou retire).
- LSL #0 = identite : les instructions registre du Lab 4 (bits 11:4 = 0)
  gardent le meme comportement.

Tests :
- phase4/sim/S1.hex ... S10.hex + S1.trace ... S10.trace (format des traces B1-B8).
- Attendus generes par phase4/scripts/gen_shift_tests.py, un modele ARM ecrit
  a partir de la specification (independant du VHDL).
- Banc : phase4/sim/tb_shift_catalog.vhd (generics PROGRAM_FILE / EXPECTED_FILE / TEST_ID).
  Chaque cycle verifie PC, Instr, ALUResult, WriteData, Flags, RegWrite,
  MemWrite, PCSrc, FlagWrite, CondEx, PC suivant et R0-R14.

Reproduction :
  Depuis la racine du depot : vivado -mode batch -source phase4/prepare_shift.tcl
  (ou Tools > Run Tcl Script dans Vivado). Le script cree phase4/vivado_shift,
  simule S1 a S10 puis tb_mp1, copie les journaux dans preuves/hatem_shift/logs/
  et ecrit preuves/hatem_shift/Resultats_S1_S10.csv.
  Pour la capture : ouvrir phase4/vivado_shift/MP1_Shift.xpr, top simulation
  tb_shift_catalog, generics du scenario voulu, Run Behavioral Simulation.

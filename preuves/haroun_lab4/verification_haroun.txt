sim/tb_arm_lab4.vhd et les deux fichiers texte decomprimes ont ete utilises.

Pour reproduire : creer un projet local VHDL-2008, ajouter les 17 fichiers de
src/ comme Design Sources, puis les trois fichiers de sim/ comme Simulation
Sources. Tops : arm_lab4 et tb_arm_lab4. Lancer Run Simulation > Run Behavioral
Simulation. Les deux .txt doivent etre exportes ou copies sans transformation
dans le repertoire XSim ; le testbench garde ses chemins relatifs d'origine.
Le projet local de cette execution est situe hors depot, dans
../verification_haroun_lab4/vivado/Haroun_Lab4.xpr.

Le CSV joint recoupe ces valeurs dans le VCD a 1 ps avant chaque front.

LT ET FLAGS
A 130 ns, instruction 12 : PC=0x2C, Instr=0xB2857001 (ADDLT R7,R5,#1).
ALUFlags=0000, Flags=1000, CondEx=1, RegWrite=1, FlagWrite=00.
Les flags sauvegardes proviennent de SUBS R8,R7,R2 : 3-5=-2.
LT teste N different de V, soit 1 different de 0 : l'addition est autorisee.
Sans S, elle ne remplace pas les flags sauvegardes, meme si l'ALU calcule 0000.
Le testbench confirme explicitement ce controle au front de 135 ns.

FIN DU PROGRAMME ET CONCLUSION
Apres le dernier front de 215 ns, PC atteint 80 (0x50) et les sorties peuvent
changer. A 230 ns : ALUResult=0 et WriteData=0, tandis que les attendus restent
0x64 et 0x0A. Ces etats posterieurs a Done ne sont pas de nouvelles erreurs.
Conclusion : validation du programme Lab 4 fournie reussie, sans correction.
Cette verification ne valide pas les extensions du mini-projet.
